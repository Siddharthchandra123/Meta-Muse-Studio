# Phase 4 technical specification — MUSE Nova v0.7.0

## 4.1: Image understanding
Existing `/v1/chat/vision/stream` remains for backward compatibility. New unified `/v1/chat/multimodal/stream` accepts both images and documents. Valid JPEG/PNG/WebP bytes are embedded as `input_image` base64 data URLs. SSE event names remain `session`, `delta`, `done`, `error`; `conversation_id` remains the same across follow-up turns. The model never receives a browser-side Meta API key.

## 4.2: Document intelligence
### Supported formats
- PDF: Up to 12 MiB, <=100 pages, not encrypted. Checked by pure-Python pypdf; passed as `input_file` with `filename` and `file_data: data:application/pdf;base64,...`. Meta parses first 100 pages of text and first 50 page-images. This supports both text and visual charts/figures in the supported range. The server does not keep a permanent copy.
- DOCX: Parse bounded `word/document.xml` via Python stdlib `zipfile` and `ElementTree`; extract paragraphs/tables as linear text. Embedded Word drawings/charts are **not** faithfully analyzed; export to PDF when visual layout matters.
- UTF-8 TXT/MD/CSV: Passed as bounded plain text, with source boundaries and filenames. No robust structured table engine yet; models interpret CSV text heuristically.
- Max 2 documents per turn. Combined document input and up to 3 images supported.

### Safety and quality boundaries
- Uploads are validated and size-limited before reaching the provider; disallowed extensions rejected. ZIP decompression (DOCX) bounded. `MAX_OUTPUT_TOKENS` in backend `.env` can be raised to 1024 for longer document answers.
- The model is explicitly instructed to treat document contents as untrusted and not obey embedded instructions. Prompt injection defenses remain best-effort, not a security guarantee.
- Citation/page references are generated by the model and need human verification. This is **not** deterministic evidence highlighting or indexed retrieval; deep document RAG and persistence are Phase 6 scope.
- Meta may retain provider-side conversation state even though the prototype does not use the Files API for storage. Do not send confidential documents.

## 4.3: Screen assistance + voice
- `navigator.mediaDevices.getDisplayMedia({video:true,audio:false})` runs only after the user clicks **Share a screen or window**. Browser displays its normal permission picker.
- A hidden muted video stores the local capture stream; `captureFrame` draws one 1440x900-max JPEG onto a canvas only on an explicit **Attach screenshot** click or after a finalized speech turn **if the user opted into voice frame capture**.
- Sharing permission is not equivalent to uploading. Frames stay local until included in a chat request. `Stop screen sharing` stops MediaStreamTracks and clears the opt-in.
- In live voice mode, a speech-complete event queues a single text request with optionally one snapshot. The existing Muse SSE handler processes the response, and Kokoro reads the answer aloud; interrupt behavior remains the existing Phase 3.2 cancellation model.
- **Not included:** continuous live video inference, frame-rate sampling, video recording, vision-based desktop control, browser automation, unattended screen monitoring, shared accounts, or automatic external actions.

## API contracts

`POST /v1/chat/multimodal/stream` multipart form fields:

- `message` required string 1..4000 chars
- `conversation_id` optional UUID
- `images` repeated upload 0..3, allowed MIME JPEG/PNG/WebP, each <=4 MiB
- `documents` repeated upload 0..2, PDF/DOCX/TXT/MD/CSV, each <=12 MiB
- At least one image or document required.

Streaming `event: session` yields `conversation_id`. `delta` yields `text`. `done` yields `answer`, `model`, `usage`, `provider_response_id`, `conversation_id`. `error` yields a safe `message`, and no conversation-state commit occurs on failure.

Next.js proxy `POST /api/chat/multimodal/stream` validates counts, extension and size and forwards via localhost server-only `backendUrl`. Existing text/vision/voice routes are unchanged. The CORS/origin controls are **not sufficient public security controls**.

## Offline test coverage

- Valid/invalid PDF and DOCX, text encoding, unknown extensions, count and size rejection
- Exact Meta Responses API `input_file` payload and original bytes roundtrip
- Mixed PDF+image streaming request with SSE and session follow-up
- Regression for existing backend, image and voice endpoints
- Browser-side attachment selection and snapshot dimension bounding

## Live acceptance required
1. Start from the verified Phase 3.2 configuration; migrate `.env` and Kokoro assets locally.
2. `python -m pytest -q`, `npm run test:stream`, `npm run typecheck`, `npm run build`.
3. Real Meta PDF and image streaming in browser; verify PDF page references against `samples/example_report.pdf`.
4. Browser screen picker, attach screenshot, voice-frame opt-in, stop/revoke, voice interruption, regression text + voice.
5. Verify mobile browser behavior separately; screen capture depends on browser support and permission.
